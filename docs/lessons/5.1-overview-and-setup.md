# 5.1 ハンズオンの全体像と演習環境の準備

## 目的

GitHubアカウント、受講者本人が所有する演習用リポジトリ、ローカルのGit／Bash環境を準備する。GitHub Actions、merge方式、main branch用Rulesetの基本設定を行い、使い捨てUT環境面、品質ゲート、証跡がハンズオン全体でどうつながるかを理解する。

## 開始状態

- GitHubアカウントを持っていなくても開始できる。
- 公開テンプレートから自分の演習用リポジトリを作成する前である。
- ローカルに演習用リポジトリをcloneしていない。

## 終了状態

- GitHubへサインインできる。
- 受講者本人の個人GitHubアカウントをOwnerとする演習用リポジトリが作成されている。
- Repository設定Phase Aが完了している。
- WindowsではGit for WindowsとGit Bash、macOS／LinuxではterminalとGitを使用できる。
- 自分の演習用リポジトリをcloneし、Repositoryルートのworking treeがcleanである。
- `pr-ci-gate`はまだRequired checkへ登録していない。
- 5.2の初回`pr-ci-gate`成功後にRepository設定Phase Bを行うことを理解している。

## 操作手順

### 1. GitHubアカウントとローカルGit環境を準備する

[GitHubアカウント、テンプレート、ローカルGitの準備](../setup/github-account-and-template.md)を開く。

- Windowsでは[Git for Windows](https://git-scm.com/install/windows.html)を準備し、Git Bashを使用する。
- macOS／Linuxでは利用可能なterminalとGitを使用する。
- 以降のBashコマンドは、Git Bashまたは同等のBash環境で実行する。PowerShell専用手順ではない。

ローカルPCで必須なのはGitとBashである。Docker、Terraform、AnsibleはGitHub-hosted runner上で動作するため、ローカル導入は必須ではない。

### 2. 公開テンプレートから演習用リポジトリを作成する

準備手順に従い、公開テンプレート`RanamicusTechnology/11-env-hands-on`から、受講者本人の個人アカウントがOwnerの新しいリポジトリを作成する。forkではない。

GitHub FreeではPublicリポジトリを使用する。Publicを選ぶ前に、secret、token、個人情報、顧客情報、業務情報、実在システムの設定値を登録せず、教材用ダミー情報だけを使うことを確認する。

### 3. GitHub Web UIでRepository設定Phase Aを行う

[リポジトリ設定手順](../setup/repository-settings.md)のPhase Aに従う。

1. GitHub Actionsとworkflow permissionsを確認する。
2. Squash mergeとMerge commitを有効、Rebase mergeを無効にする。
3. `main-protection` Rulesetを作成する。
4. `Target branches` → `Add target` → `Include default branch`でdefault branchを対象にする。
5. Required checkを追加せず、Enforcement statusを`Disabled`で保存する。

### 4. ローカルGitで自分の演習用リポジトリをcloneする

GitHub Web UIで作成・設定した自分の演習用リポジトリをcloneする。講師の公開テンプレートを直接cloneして編集しない。
以下のコマンドの`<任意のリポジトリ配置先フォルダ>`、`<account>`と`<repository>`を自分の値へ置き換えて、git bashで実行する。

```bash
cd "<任意のリポジトリ配置先フォルダ>"
git clone https://github.com/<account>/<repository>.git
cd <repository>
git status
```

`cd`後のRepositoryルートで、`git status`がcleanであることを確認する。以降のコマンドは、特に記載がない限りこのRepositoryルートで実行する。

### 5. 5.2へ持ち越す設定を確認する

新しいリポジトリには、まだ`pr-ci-gate`の成功履歴がない。5.2でIssue、feature branch、Draft Pull Requestを作成し、最小PR CIの`pr-ci-gate`がsuccessになった後にPhase Bを行う。

Phase Bでは、同じ`main-protection` Rulesetへ`pr-ci-gate`をRequired checkとして追加し、`Require branches to be up to date before merging`を有効にして、Enforcement statusを`Active`へ変更する。

## Web UIとローカル操作の境界

```text
GitHub Web UI: Templateから演習Repositoryを作成
→ GitHub Web UI: Repository設定Phase A
→ ローカルGit／Bash: clone、Repositoryルートへ移動、clean確認
→ 5.2: GitHub Web UIでIssue、ローカルGitでbranchと変更、GitHub Web UIでDraft PR
```

## ハンズオン全体で扱う関係

品質ゲートはPull Request作成を禁止するものではなく、不備のある変更がmainへmergeされることを防ぐ。変更Issueには変更要求、受入条件、変更対象、`target_version`、`required_final_stage`を記録する。

Test run ID、Environment face ID、Build Artifact IDなどの実行時情報はGitHubまたはworkflowが生成する。受講者がIssue本文へ固定値として入力しない。

Build Artifactはchecksumで同一性を確認する。テスト結果と証跡はjobごとのActions Artifactとして管理し、Job SummaryをTest run ID、Issue、Pull Request、workflow run、job結果、Artifact名の索引として使用する。

## 5.1完了チェック

- [ ] 自分がOwnerの独立した演習用リポジトリをTemplateから作成した。
- [ ] GitHub Actions、workflow permissions、merge方式を確認した。
- [ ] `main-protection`はdefault branchを対象にし、Required checkなし、`Disabled`で保存した。
- [ ] GitとBashを利用できる。
- [ ] 自分の演習用リポジトリをcloneした。
- [ ] Repositoryルートで`git status`がcleanである。
- [ ] Docker、Terraform、Ansibleのローカル導入は必須ではないと理解した。
- [ ] `pr-ci-gate`は5.2の初回成功後に追加すると理解した。
